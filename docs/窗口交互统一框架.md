### 1.3 优先级排序

排序依据：**影响面 × 可复现性 × 违反用户直觉的程度**。

| 优先级 | 编号 | 问题 | 理由 |
|---|---|---|---|
| **P0（必须修）** | C1 / C2 | Z 序覆盖缺失 | 窗口模型的地基。不修则"多窗口"名不副实，且 A1/D1 的修法都依赖"谁是活动窗口"能被正确表达 |
| **P0** | A1 | 关闭语义错位 | 开始菜单是最高频入口，误关主页会丢失正在看的内容，最伤 |
| **P0** | D1 / D2 | 显示设置不可达 | 用户明确反馈"无响应"，属功能性失效 |
| **P1（应当修）** | B1 / B2 / B3 | 位置记忆 | 高频操作（每次拖动都可能丢失），且需要新增持久化层，工作量中等 |

| **P1** | A2 | 任务栏图标残留 | 由 A3 的状态机统一后自然消解 |
| **P2（优化）** | — | 主窗口缺"点击聚焦"、三份 `pinToPixels` 分叉、缺少 CSS transition | 属体验与代码健康度，不修也能工作 |

## 第二步：统一的窗口交互框架

### 2.0 分层架构

```
┌──────────────────────────────────────────────────────────┐
│  WinWM（窗口管理器单例，app.js 定义，全局唯一）           │
│  ├─ 注册表 reg[ id ] → { el, taskBtn, api, state }       │
│  ├─ Z 序管理：zBase + 每次聚焦 +1，写回 el.style.zIndex  │
│  ├─ 焦点管理：activeId；唯一入口 focus(id)               │
│  ├─ 状态机：normal / minimized / closed（+maximized 修饰）│
│  └─ 持久化：位置 & 状态写入 localStorage（带命名空间）    │
└───────┬──────────────┬──────────────┬────────────────────┘
        │              │              │
   主窗口 #win     记事本 #winNp    播放器 #winMp
   （各模块只登记 el / taskBtn / 生命周期回调，业务自管）
```

**核心原则**：所有窗口**显隐/聚焦/层级/持久化**都只能走 `WinWM` 的公开方法；各模块不再自己
`classList.add('is-hidden')`、不再自己改 `z-index`、不再自己 clamp。模块只负责"内容"。

### 2.1 状态机（单一真相源）

对每个窗口维护 `state ∈ { normal, minimized, closed }`，另有正交修饰 `maximized ∈ {true,false}`。

```
                 ┌──────── minimize() ────────┐
                 ▼                            │
   ┌─────────┐        restore()         ┌────────────┐
   │ normal  │ ◄─────────────────────── │ minimized  │
   └─────────┘                          └────────────┘
        │  ▲                                  │
 close()│  │open()/restore()                  │close()
        ▼  │                                  ▼
   ┌─────────┐                                │
   │ closed  │ ◄──────────────────────────────┘
   └─────────┘
```

| 状态 | 窗口 DOM | 任务栏按钮 | 音频 | 可被 restore | 位置持久化 |
|---|---|---|---|---|---|
| `normal` | 可见 | 可见 + 高亮(若 active) | 播放器按播放态 | — | ✅ 写盘 |
| `minimized` | 隐藏 | **可见但不隐藏**（Windows 经典语义：最小化后按钮仍在） | 播放器暂停 | ✅ 点击按钮恢复 | ✅ 写盘 |
| `closed` | 隐藏 | **隐藏** | 播放器停止(pause+归零由用户决定) | ✅ 可重新 open | ✅ 写盘（含"上次是关闭态"） |

> **修正 A3/A2 的关键**：`minimized` 保留任务栏按钮，`closed` 移除任务栏按钮 —— 这在视觉上
> 与功能上同时区分了"最小化"和"关闭"。当前三窗口对按钮的处理相反（主窗口永不隐藏、另两个都隐藏），
> 统一后**三窗口一致**。

### 2.2 行为规则（逐条对应需求）

#### (1) 关闭 Close
- **语义**：结束窗口实例的"打开态"。窗口隐藏、任务栏按钮隐藏、播放器音频暂停。
- **动画**：窗口 `transform` 缩放到**任务栏按钮中心**并淡出。**必须有 CSS `transition`**：
  `.window { transition: transform .24s ease, opacity .24s ease; }`（当前缺失 → 动画生硬/瞬变，一并修）。
- **与任务栏图标联动**：`closed` → 按钮加 `.is-hidden`；但**顺序必须正确** —— 先在动画开始前
  记录按钮 rect，动画**结束后**（240ms）再隐藏按钮与窗口本体，避免 A2 的"图标残留"。
- **关闭后可否唤回**：可以（点桌面图标 / 开始菜单重新打开）。但**不**再借任务栏按钮（按钮已隐藏）。

#### (2) 最小化 Minimize
- **语义**：保留任务实例。窗口隐藏，**任务栏按钮保留**（仅去掉高亮）。
- **与关闭的视觉区分**：
  - 动画相同（都缩向任务栏），但 **最小化的终点是任务栏按钮、且按钮保留并短暂"脉冲"高亮**；
  - `closed` 的按钮消失，`minimized` 的按钮**保留**（这是最直接的视觉判据）。
- **状态恢复路径**：点击任务栏按钮 → `restore()` → 回到 `normal` 并 `focus()`；
  `restore` 时若之前是 `maximized`，则恢复到最大化。
- 播放器：最小化时 `pause()`（避免后台出声），恢复后**不自动播放**（符合原生行为）。

#### (3) 聚焦 Focus
- **判定标准**：`activeId === id` 且窗口处于 `normal`。同一时刻**至多一个**活动窗口。
- **触发方式**（统一）：
  1. 在窗口内任意处 `mousedown`（含标题栏、内容区）→ `focus(id)`；
  2. 点击任务栏按钮（非活动时）→ `focus(id)`；
  3. 程序化 `open()` / `restore()` 末尾 → `focus(id)`。
- **副作用**（`focus(id)` 必须原子完成）：
  - `activeId = id`；
  - 该窗口 `z-index = ++maxZ`（置顶）；
  - 该窗口去 `.is-inactive`、任务栏按钮加 `.is-active`；
  - 其它所有已登记窗口加 `.is-inactive`、按钮去 `.is-active`；
  - 写盘"上次聚焦的窗口"（可选，用于刷新后恢复焦点感）。

#### (4) 层级 / Z 序
- **覆盖顺序**：由 `z-index` 唯一决定（不再依赖 DOM 顺序）。
  - 基础层：`.desk-icons` 1、`.window` 5（起始）；
  - 每次 `focus` 把该窗口 `z-index` 提到 `WM.maxZ + 1`，`maxZ` 单调递增（防溢出时可重排归一化）；
  - 浮层保持在其上：`.taskbar` 100、`.startmenu` 120、`.toast` 130、`.modal-mask` 200、`.dialog` 210。
- **点击聚焦的提升规则**：**点击即可见窗口的任意位置**（捕获阶段监听），立即 `focus(id)` 并置顶；
  若该窗口此时是 `minimized`，点击任务栏按钮走 `restore()` 而非 `focus()`。
- **被遮挡窗口的查看**：点任务栏按钮或点其任意可见部分 → 立即提升到最前（修 C1/C2）。

#### (5) 位置记忆
- **持久化时机**（去抖写入，避免拖动中高频写盘）：
  - 拖动 `dragEnd` 后；
  - 最大化/还原后（**保存的是 normal 态几何**，不是 maximized 的满屏几何）；
  - 最小化/关闭前（保存当前 normal 几何）；
  - 视口 `resize` 后重 clamp 完；
  - 每窗口去抖 200ms 合并写入。
- **恢复条件**：`open()` 时若存在记录且**记录与当前视口相容**（宽度 ≤ 桌面宽、位置在当前视口可达范围内）则套用；
  否则回退到 `pinToPixels()` 的默认锚定。
- **与最小化/最大化的冲突处理**：
  - `maximized` 期间**不写** normal 几何（避免把满屏坐标当常态）；
  - 退出最大化时恢复 `savedRect`（这是"几何"恢复，与"位置记忆"是两回事，需区分）；
  - **关键修正 B2**：`savedRect` 采用"进入最大化那一刻的几何"，且拖动会**更新** `savedRect`
    （即 `savedRect` 恒等于"最近一次 normal 态几何"）；这样"拖动 → 最大化 → 还原"不会丢失拖动结果。
  - 存储键：`winclassic.wm.v1.<id>.rect` / `.state`；带 `v1` 版本号便于日后迁移。
  - 读取失败（JSON 损坏 / 隐私模式禁用 storage）一律静默降级，不影响功能。

### 3.3 验收用例（用于第四/五步自测）

1. 打开三个窗口，依次点击每个窗口内容区 → 该窗口必须**视觉置顶**（`z-index` 最大）。
2. 点击任务栏按钮（非活动）→ 置顶且高亮；再点一次 → 最小化且**按钮保留**。
3. 关闭播放器 → 按钮**消失**；最小化播放器 → 按钮**保留**。
4. 拖动播放器到任意位置 → 失焦再聚焦 → **位置不变**（修 B1）。
5. 拖动 → 最大化 → 还原 → 位置**保持拖动后的坐标**（修 B2）。
6. 刷新页面 → 三窗口位置与最后状态**被记住**（修 B3）。
7. 主窗口最小化时点开始菜单"显示设置" → 主窗口**自动恢复并滚动到对应区域**（修 D1）。
8. 播放器聚焦时点开始菜单"关闭窗口" → **关闭播放器**而非主页（修 A1）。
9. 无未捕获 JS 异常；EdgeHTML 18 禁用清单命中为 0。
